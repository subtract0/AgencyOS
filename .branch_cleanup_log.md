## Investigation Methodology

### Analysis Performed
1. **Commit Count**: `git log main..$branch --oneline --no-merges | wc -l`
2. **NET Line Count**: `git diff main..$branch --shortstat`
3. **Unique Files**: `git diff main..$branch --name-only`
4. **Commit Messages**: `git log main..$branch --format="%s" --no-merges`
5. **File Existence**: Verified kanban files, distributed locking files in main

### Decision Criteria
- **Empty**: NET negative lines (massive deletions) = outdated branch behind main
- **Diverged**: NET positive >100K lines with >1000 files = parallel timeline, not unique work
- **Superseded**: Unique commits but file content already in main (e.g., kanban files)
- **Duplicate**: Identical NET lines across branches (e.g., feat/test-suite-state-of-the-art = feat/phase-2ab-mars-ready-complete)

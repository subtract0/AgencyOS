## Mission Objective

Create and run a **continuous read-only auditing system** that scans the entire AgencyOS codebase and generates numbered recommendation files using local M4 Pro agents.

---

## User Requirements (Finalized)

### **1. Scope**: ALL
- Scan entire codebase (all agents, shared, trinity, tools, tests, docs)
- No exclusions - comprehensive audit

### **2. Priorities**: ALL
- Consolidation (DRY violations)
- Linting (style issues)
- Simplification (complexity reduction)
- Pruning (dead code removal)
- Architecture (design improvements)

### **3. Quantity**: ALWAYS ALL
- Generate separate file for EACH recommendation
- **Smart Deduplication**: Before creating new file, check if related recommendation exists
  - If related file exists: APPEND to that file and elevate its priority/relevance
  - If new issue: Create new numbered file
- No limits on number of recommendations

### **4. Mode**: CONTINUOUS
- Run until manually stopped OR 48-hour wall-clock timeout
- Continuously scan and generate recommendations
- Track progress and prevent duplicate scans

### **5. Output Location**: `localaudit_recommendations/`
- Directory: `localaudit_recommendations/` (create if not exists)
- File format: `localM4_recommends_XXX-title.md` where XXX is zero-padded number (001, 002, etc.)
- Metadata tracking file: `localaudit_recommendations/.audit_state.json`

## System Architecture

### **Agent Pipeline**

```
Continuous Loop (48h max):
  1. AUDITOR → Scan code, find issues
  2. QUALITY_ENFORCER → Check constitutional compliance
  3. LEARNING → Extract patterns, check for related issues
  4. PLANNER → Prioritize and format recommendation

  For each finding:
    - Check if related recommendation exists (similarity match)
    - If exists: Append to existing file, elevate priority
    - If new: Create new numbered file

  Sleep 5-10 minutes between scans
  Track scanned files to avoid redundant work
```

## Best Practices

### **Code Quality**
- ✅ Use AgentContext for memory/learning
- ✅ Use Result<T,E> pattern for error handling
- ✅ Pydantic models for all data structures (no Dict[Any,Any])
- ✅ Type hints everywhere
- ✅ Docstrings for all functions
- ✅ TDD: Write tests FIRST

### **Performance**
- ✅ Batch file reads where possible
- ✅ Cache analysis results
- ✅ Sleep between scan cycles (avoid CPU thrashing)
- ✅ Progress tracking (don't re-scan same files)

### **Safety**
- ✅ READ-ONLY operations only
- ✅ No file writes except recommendation files
- ✅ Graceful shutdown on SIGINT
- ✅ Timeout protection (48h max)

### **Monitoring**
- ✅ Telemetry events to message bus
- ✅ Progress logs (console + file)
- ✅ State persistence (resume after crash)
